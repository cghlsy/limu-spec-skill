# 按需生成可编辑图示

图示服务于理解和审查，不是每个阶段的固定产物。优先画一张能解释关键关系的图，避免把整份规格或所有代码复制成图。

## 何时画、画什么

用户明确要求图示时生成；否则仅在多个角色、复杂分支与状态、跨模块调用、异步时序或数据关系难以通过简短文字理解时生成。

| 场景 | 建议图示 | 关注内容 |
|---|---|---|
| 需求规划、业务流程审查 | 流程图、泳道图 | 操作顺序、角色职责、决策点、异常出口 |
| 生命周期、状态规则 | 状态转换图 | 状态、转换条件、失败与重试 |
| 技术设计 | 架构图、时序图、数据流图 | 模块边界、接口调用、异步交互、数据去向 |
| 数据关系规划 | ER 图 | 与本次改动相关的实体和关系 |
| 代码审查 | 调用关系图、时序图、状态图 | 缺陷触发路径、竞态、影响范围 |

单一关系可直接用 Markdown 表格或 Mermaid。用户指定 draw.io 或可编辑图示时，优先满足指定格式；不要因格式偏好扩大分析范围。

## 调用 drawio-skill

1. 在当前环境的技能目录或技能清单中查找 `drawio-skill`，读取其 `SKILL.md` 和本次图示类型需要的参考文件。不要硬编码某个用户的技能路径，不复制其生成工具到本技能。
2. 告知用户将使用 drawio-skill，并传入图示目的、读者、范围、类型、输出路径，以及已核实的节点、连接、条件和对应来源。沿用原任务的授权和停点。
3. 按该技能选择生成或更新方式，产出原生可编辑 `.drawio`，执行结构校验。仅在图涉及的策略或语义需要验证时增加对应检查。
4. 在工具可用时导出 PNG 等预览并检查重叠、截断、连线和标签。沿用该技能的导出约定；不要把未经渲染检查的结果描述为视觉验证通过。
5. 技能不可用时，说明原因，可先提供 Mermaid 或文字关系表，不自动安装。明确要求 `.drawio` 时，注明格式要求尚未完成。可编辑源已生成但导出环境缺失时保留源文件，说明未完成的预览与检查。

此处是可选技能依赖，不是 MCP 工具依赖。没有 drawio-skill 也应完成不依赖它的规格、设计或审查工作。不得为画图自动上传项目源码或图示到在线服务；需要渲染时优先使用本地方式。

## 图示内容与依据

- 图中显式注明“当前实现”“目标方案”或“问题触发场景”。需要比较前后行为时，用独立页面或清晰分区，不能混成一张无标识的事实图。
- 需求图节点或边引用 `F`、`E`、`R` 编号；代码图保留可追溯的模块、函数或源路径。详细规则和缺陷说明仍在 Markdown 中定义一次。
- 当前实现关系应来自实际读取的代码或文档。静态调用关系不等于已观测的运行路径；推断、待确认和方案关系使用明确标签或线型区分，并提供图例。
- 只呈现解释本次需求或发现所必需的部分。存在多个问题时，不为每条简单发现都新建图。

## 文件、引用与更新

沿用项目已有产物目录。无约定时，规格或设计图放在该需求目录的 `diagrams/` 下，使用如 `business-flow.drawio`、`state-transitions.drawio`、`interaction-sequence.drawio` 等语义名称。代码审查图跟随已有审查报告目录；没有报告或用户指定位置时，在项目的 `docs/reviews/<本次审查短名>/diagrams/` 保存必要图示，不创建额外报告模板。没有项目目录时遵循当前工作区的输出约定。

在对应 Markdown 章节链接 `.drawio` 源文件，有预览时用相对路径嵌入图片。最终说明源文件及预览位置；不得把单张 PNG 当成可编辑源文件。

已有图优先增量更新，保留节点身份和人工布局。源规格或代码变化时，只更新受影响的关系并重新检查；过期图应修正或移除引用，不能继续作为当前事实。只有实际生成且存在的文件才加入文档链接。

只读审查不修改业务代码。用户明确禁止任何文件写入时，在对话中提供文字或 Mermaid 图示；没有此限制时，可输出独立审查图示，但不自动重写现有报告或规格。
